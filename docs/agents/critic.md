# Critic Agent

The **Critic Agent** acts as the quality assurance layer for Autonoma. It reviews the plans and tool calls generated by the other agents to ensure they are logical, efficient, and statistically sound.

## 🎯 Objectives
- Validate the logic of proposed tool calls.
- Prevent data leakage (e.g., scaling before splitting).
- Ensure that chosen models match the problem type (Classification vs. Regression).
- Provide constructive feedback to agents when a plan is rejected.

## 🧠 Reasoning Logic
The Critic is a specialized prompt that reviews the `sample_output` (the JSON tool calls) of the `current_agent`. 

It outputs a JSON response with three keys:
1. `final_decision`: Either `"approve"` or `"revise"`.
2. `critic_feedback`: Detailed reasoning for the decision.
3. `critic_iterations`: Number of critic iterations.

### Safety Mechanisms
- **Max Iterations**: If the Critic rejects plans more than `MAX_CRITIC_ITERATIONS` times, the system forces an approval to prevent the pipeline from hanging.
- **JSON Fallback**: If the Critic fails to generate valid JSON, the system defaults to "approve" to maintain flow.

## 🛠️ Routing Impact
The Critic's decision directly affects the LangGraph workflow:
- **Approve**: Moves to the **Executor** node.
- **Revise**: Loops back to the agent that generated the plan, passing the `critic_feedback` into their prompt.
